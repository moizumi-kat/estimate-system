# 記号認識（テンプレートマッチング）設計メモ

**状態：研究プロトタイプで実証済み／本番未実装（2026-11）**
担当：茂泉様　／　目的：①確認ビューアの着色を正確に ②抽出精度を記号ベースで底上げ

---

## 0. 背景・ねらい

この会社の図面は記号が図形化され、文字座標が取れない（pdftotext は凡例のみ）。
これまでの着色は「四角い範囲＋線の太さ」で判定していたため、**配線・隣接機器を巻き込む**限界があった。

そこで **記号認識（テンプレートマッチング）** に切り替える。狙いは2つ：

- **(A) 確認ビューアの着色**：その機器の記号だけを正確に着色（配線・隣・文字を巻き込まない）。
- **(B) 抽出精度の底上げ（茂泉様ご指摘・重要）**：文字頼みの抽出に「**記号を数える**」軸を加える。
  文字がかすれ・省略される図面でも、記号から「変圧器4台」「ZCT4個」を**図形で直接確定**できる。

---

## 1. 実証できたこと（サンドボックス・実図面 神田の杜 E-001）

- **1記号1手本で自動検出**：変圧器の二重丸を1つ手本にし、図面から**変圧器4台を自動検出**（一致度 0.82〜1.00）。
- **配線除外**：モルフォロジーで直線（配線）を抽出・除外し、**丸記号だけ着色**（中央の縦線・引き出し線は黒のまま）。
- **複数記号の同時認識・色分け**：TR=赤／ZCT=青／ELR=緑／SC=紫／LBS=青緑。
  検出数：TR 4・ZCT 4・ELR 4・SC 2・LBS 6。
- **TR・ZCT・ELR の分離**：別記号として切り離して認識・着色（従来の巻き込みが解消）。

### 実証で見えた課題（正直な記録）
- **似た記号の誤検出**：LBS 手本が **VMC 箱**も拾い 6個（本来4個）。箱＋斜めスイッチで形が酷似。
  → **文字（"LBS"/"VMC"）のOCRで区別**、または手本を厳密化。
- **大きさ違い**：別ページ・別縮尺で記号サイズが変わると単一スケールでは漏れる → **多スケール照合**で対応。
- **重なり**：記号が配線・文字と密着する箇所は取りこぼし得る（大半はクリーン）。

## 2. 本番アーキテクチャ（案）

```
図面PNG(fitz) ─┬─> [記号検出] テンプレ照合(多スケール)+NMS ──> 記号リスト {種別, 位置, スコア}
               │                                           │
               ├─> [配線マスク] モルフォロジーで直線抽出     ├─> (A)着色: 記号ink ∩ ¬配線 を記号色で塗る
               │                                           │
               └─> [OCR/Vision] 記号近傍の文字(名称/定格)   └─> (B)抽出: 記号カウント × 文字抽出 を突き合わせ
```

### 2-1. 記号ライブラリ（一度の整備で使い回し）
- **出所＝図面の〈凡例〉**。主要記号の手本を一式：
  VCB / LBS / DS / PAS(UGS) / CT / ZCT / VT / PF / LA / SC / SR / VMC / MCCB / ELB / ELR(EL) / 計器(A/V/WH/マルチ) / TR 等。
- 手本は **二値化＋直線除去済みのマスク**として保持（照合は原画、着色はマスク形状で）。
- 凡例は案件で微妙に異なり得る → **凡例から毎回手本を自動生成**できると理想（凡例表のセルを切り出し）。

### 2-2. 検出パイプライン
- `cv2.matchTemplate`（TM_CCOEFF_NORMED）＋**非最大抑制(NMS)**。
- **多スケール**：0.8〜1.3 倍を数段階、最良スコアを採用。
- **似た記号の後処理**：候補近傍を**OCRでラベル判定**し種別を確定（LBS/VMC、CT/ZCT 等）。
- 失敗・低スコアは**出さない**（◎誤答ゼロ：記号は確信があるものだけ確定、曖昧は△）。

### 2-3. (A) 着色（確認ビューア）
- 現行の「範囲＋線太さ」判定を**記号検出ベースに置換**。
- 塗るのは **記号ink ∩ ¬配線マスク**。選択=赤／確認済=青（§10 の現行UI方針を踏襲）。
- 位置が正確なので、リスト↔図面の対応が確実に。advisory（積算額に無影響）は不変。

### 2-4. (B) 抽出への組み込み（精度向上の本命）
- **記号カウント × 文字抽出（二重Vision）**の三重突き合わせ：
  - 記号数 == 文字抽出数 → **◎（図形と文字が一致）**
  - 不一致 → **△（人が確認）**＝安全側（◎誤答ゼロ原則）
- 文字がかすれても記号で台数を確定でき、**取りこぼしを捕捉**。
- 盤種・機器種の**配置（記号の位置関係）**も手掛かりになり得る（受電→TR→低圧盤の縦系統 等）。

## 3. 技術前提・コスト

- **ライブラリ**：OpenCV（`opencv-python-headless`）＋numpy。本番EC2へ追加（サーバ側処理）。
- **処理コスト**：照合は軽い（1図面あたり数百ms〜数秒／記号種×スケール）。Vision抽出に比べ安価。
- **精度**：クリーンなCAD線画で有効。手書き崩れ・特殊記号・密集は取りこぼし得る（△で安全側）。
- **再現性**：決定的（同一図面→同一結果）。方針1-5と整合。

## 6. 記号辞書の整備完了と選定エンジン組み込み設計（2026-11・ウ）

### 6-1. 実施済み（支給図面18案件から辞書化）
Dropbox「参考図面」の**全図面（コード無し案件も含む）**の凡例を抽出し、名寄せ・db照合まで完了。
- **マスター記号辞書** `symbol_master_dictionary.json`：正規デバイス **57種**。各デバイスに〔別名(方言)集合／ANSI機器番号／db.json実在コード系統〕を付与。
- **別名辞書** `symbol_alias_map.json`：**別名113種**→正規デバイス＋コードの正規化lookup。多義3（`52`=VCB/接触器, `VS`=高圧真空開閉器/切換SW, `DTMC`=電源切替/動力MCCB）。
- **db.json照合**：主要記号は実在（VCB=43001-13, TR=17/45系, SC=45100-13/53系, 計器=42系, MDA=42075-88 等）。**真のDB追加は0件**＝ZVT=44026(GVT)/CCT=46系IGR/ELR=46410/EL=既存漏電地絡系へ名寄せ、LD=防災で対象外。**方針5「新規追加せず」充足**（茂泉様確定：別名登録のみ・db.json無変更）。
- **二層構成の確立**：①図面別＝その図面の凡例で記号手本を自己校正（支給元の方言を吸収）／②マスター＝JIS/JEM標準＋別名辞書（横断の名寄せ・図面自動作成の出力元）。

### 6-2. 判明した「支給元の方言」（別名辞書で吸収）
- 変圧器 TR=T=Tr(スコット=SCTT/図記号)、進相コンデンサ SC=C、計器用変圧変流器 VCT=MOF、計器用変圧器 VT=PT、漏電遮断器 ELB=ELCB、低圧地絡 LGR=GR、電力計 W=KW、マルチ MDA=ME=MM=DM、温度計 26T=t°=θ。
- **ANSI機器番号方式**：27=UVR,51=OCR,52=接触器,55=APFC,64=OVGR,67=DGR,84=電圧継電器,26T=温度（表参道/城山/木村）。
- **二義注意**：VS(高圧真空開閉器/電圧計切換SW), PF(電力ヒューズ/力率計), T(変圧器/タイマー), EL(漏電継電器)≠ELB(漏電遮断器)。
- **対象外(建築電気)**：照明器具/配管配線/接地極/分岐回路番号(木村p3等)は盤積算の対象外。

### 6-3. 選定エンジン組み込み設計（別名辞書＝まず無リスクで効く）
```
図面 → 抽出(Vision/凡例) → 【正規化】alias_map で 記号/ANSI番号/方言 → 正規デバイス
                                        ↓
                        選定(決定的) → db.jsonコード候補（従来ロジックに前段で名寄せを噛ませる）
   （次段）記号検出(テンプレ) → 記号カウント × 文字抽出 を突合 → 一致◎/不一致△（◎誤答ゼロ）
```
- **第1段（低リスク・先行）**：抽出結果の機器名を**別名辞書で正規化してから選定**に渡す。T→変圧器、MOF→VCT、ANSI番号→略号、等を吸収＝**支給元差による取りこぼし・誤選定を削減**。選定ロジック本体は不変＝回帰ゼロ。多義(52/VS/DTMC/PF/T/EL)は文脈(位置・近傍文字・盤種)で解決、曖昧は△。
- **第2段（記号カウント突合）**：§2-4の記号検出カウント×文字抽出を選定前チェックに追加。台数一致で◎、不一致で△。
- **第3段（着色の記号検出化）**：§2-3のビューア着色を記号検出ベースへ（advisory・選定不変）。

### 6-4. 図面自動作成への再利用
同じマスター辞書を**逆引き**（正規デバイス→JIS/JEM標準記号→配置）すれば、将来の図面自動作成で標準記号を出力できる。db.json（積算）↔記号辞書↔JIS/JEM の三者連結が資産になる。

## 7. 本番組み込み（2026-11・advisory／dev反映・本番mainは出して待ち）

### 7-1. 規格照合（JIS C0617 / JEM1115・1090）完了
各テンプレートを規格図記号と**並べて照合**（農水省電気設備標準§7.3）。
- 直接一致：TR=06-09-01(二重丸), CT=06-09-10(丸+スラッシュ), ZCT=06-13-10。
- 核一致（図面は箱囲みで描く方言）：VCB=07-13-05, DS=07-13-06, VMC=07-13-02, SR=04-03-01, SC=04-02-01, LBS=07-21-09。
- JIS表から直接採取（規格そのもの）：CT様式2, ZCT様式2, VT様式1/様式2, PAS=07-13-08, PF=07-21-01, LA=07-22-03。
- 計器＝丸+文字(08系), 継電器＝JEM1090番号箱（形でなく文字/番号で判別が本筋）。
→ **御社図面は開閉機器を箱で囲む流儀**。核記号はJIS準拠なので「核＋箱」でテンプレ化（実図面に一致）と裏取り。

### 7-2. 実装（回帰ゼロ＝選定エンジン不変）
