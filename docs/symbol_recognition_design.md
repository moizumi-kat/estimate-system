# 記号認識（テンプレートマッチング）設計メモ

**状態：研究プロトタイプで実証済み／本番未実装（2026-11）**
担当：茂泉様　／　目的：①確認ビューアの着色を正確に ②抽出精度を記号ベースで底上げ

---

## 0. 背景・ねらい

この会社の図面は記号が図形化され、文字座標が取れない（pdftotext は凡例のみ）。
これまでの着色は「四角い範囲＋線の太さ」で判定していたため、**配線・隣接機器を巻き込む**限界があった。

そこで **記号認識（テンプレートマッチング）** に切り替える。狙いは2つ：

- **(A) 確認ビューアの着色**：その機器の記号だけを正確に着色（配線・隣・文字を巻き込まない）。
- **(B) 抽出精度の底上げ（茂泉様ご指摘・重要）**：文字頼みの抽出に「**記号を数える**」軸を加える。
  文字がかすれ・省略される図面でも、記号から「変圧器4台」「ZCT4個」を**図形で直接確定**できる。

---

## 1. 実証できたこと（サンドボックス・実図面 神田の杜 E-001）

- **1記号1手本で自動検出**：変圧器の二重丸を1つ手本にし、図面から**変圧器4台を自動検出**（一致度 0.82〜1.00）。
- **配線除外**：モルフォロジーで直線（配線）を抽出・除外し、**丸記号だけ着色**（中央の縦線・引き出し線は黒のまま）。
- **複数記号の同時認識・色分け**：TR=赤／ZCT=青／ELR=緑／SC=紫／LBS=青緑。
  検出数：TR 4・ZCT 4・ELR 4・SC 2・LBS 6。
- **TR・ZCT・ELR の分離**：別記号として切り離して認識・着色（従来の巻き込みが解消）。

### 実証で見えた課題（正直な記録）
- **似た記号の誤検出**：LBS 手本が **VMC 箱**も拾い 6個（本来4個）。箱＋斜めスイッチで形が酷似。
  → **文字（"LBS"/"VMC"）のOCRで区別**、または手本を厳密化。
- **大きさ違い**：別ページ・別縮尺で記号サイズが変わると単一スケールでは漏れる → **多スケール照合**で対応。
- **重なり**：記号が配線・文字と密着する箇所は取りこぼし得る（大半はクリーン）。

## 2. 本番アーキテクチャ（案）

```
図面PNG(fitz) ─┬─> [記号検出] テンプレ照合(多スケール)+NMS ──> 記号リスト {種別, 位置, スコア}
               │                                           │
               ├─> [配線マスク] モルフォロジーで直線抽出     ├─> (A)着色: 記号ink ∩ ¬配線 を記号色で塗る
               │                                           │
               └─> [OCR/Vision] 記号近傍の文字(名称/定格)   └─> (B)抽出: 記号カウント × 文字抽出 を突き合わせ
```

### 2-1. 記号ライブラリ（一度の整備で使い回し）
- **出所＝図面の〈凡例〉**。主要記号の手本を一式：
  VCB / LBS / DS / PAS(UGS) / CT / ZCT / VT / PF / LA / SC / SR / VMC / MCCB / ELB / ELR(EL) / 計器(A/V/WH/マルチ) / TR 等。
- 手本は **二値化＋直線除去済みのマスク**として保持（照合は原画、着色はマスク形状で）。
- 凡例は案件で微妙に異なり得る → **凡例から毎回手本を自動生成**できると理想（凡例表のセルを切り出し）。

### 2-2. 検出パイプライン
- `cv2.matchTemplate`（TM_CCOEFF_NORMED）＋**非最大抑制(NMS)**。
- **多スケール**：0.8〜1.3 倍を数段階、最良スコアを採用。
- **似た記号の後処理**：候補近傍を**OCRでラベル判定**し種別を確定（LBS/VMC、CT/ZCT 等）。
- 失敗・低スコアは**出さない**（◎誤答ゼロ：記号は確信があるものだけ確定、曖昧は△）。

### 2-3. (A) 着色（確認ビューア）
- 現行の「範囲＋線太さ」判定を**記号検出ベースに置換**。
- 塗るのは **記号ink ∩ ¬配線マスク**。選択=赤／確認済=青（§10 の現行UI方針を踏襲）。
- 位置が正確なので、リスト↔図面の対応が確実に。advisory（積算額に無影響）は不変。

### 2-4. (B) 抽出への組み込み（精度向上の本命）
- **記号カウント × 文字抽出（二重Vision）**の三重突き合わせ：
  - 記号数 == 文字抽出数 → **◎（図形と文字が一致）**
  - 不一致 → **△（人が確認）**＝安全側（◎誤答ゼロ原則）
- 文字がかすれても記号で台数を確定でき、**取りこぼしを捕捉**。
- 盤種・機器種の**配置（記号の位置関係）**も手掛かりになり得る（受電→TR→低圧盤の縦系統 等）。

## 3. 技術前提・コスト

- **ライブラリ**：OpenCV（`opencv-python-headless`）＋numpy。本番EC2へ追加（サーバ側処理）。
- **処理コスト**：照合は軽い（1図面あたり数百ms〜数秒／記号種×スケール）。Vision抽出に比べ安価。
- **精度**：クリーンなCAD線画で有効。手書き崩れ・特殊記号・密集は取りこぼし得る（△で安全側）。
- **再現性**：決定的（同一図面→同一結果）。方針1-5と整合。

## 4. 段階計画（提案）

1. **記号ライブラリv0**：凡例から主要10〜15記号の手本を整備（神田の杜で作成→他案件で検証）。
2. **検出器v0**：多スケール照合＋NMS＋OCRラベル判定。実図面で検出率・誤検出を実測。
3. **(A)着色の置換**：確認ビューアの着色を記号検出ベースへ（回帰ゼロ＝advisory・選定不変）。
4. **(B)抽出突き合わせ**：記号カウントを選定前チェックに追加（◎/△判定の強化）。まず「台数カウント」から。
5. **評価**：手本のある案件（神田の杜/船橋/練馬/武蔵野美大/銀座二丁目 等）で、記号抽出と手本の一致を実測。

> 方針1-1（裏取り）：各段階で**実図面・実手本で検証**してから進める。blind実装はしない。
