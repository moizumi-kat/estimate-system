# From-To アドオン 出力データ仕様書（設計CAD → 製造）

対象: 古川電気工業（制御盤／分電盤ハーネス）
版: ドラフト v0.1
目的: 設計CAD側のアドオンが「結線の意図（From-To・号線・等電位ノード）」を構造データとして
図面に書き出し、製造側がそれを読んでハーネスシート・主回路・検図・1本表示を生成する。

---

## 0. なぜこの仕様が必要か（背景）

図面からの**幾何抽出だけでは正確な From-To は得られない**ことが検証で判明した。

- 図面は結線を「作図の約束事」で表す：**同じ号線＝同じ線**、**同じ名前＝同じ機器**、
  **横レール＝母線**、**ドットのある交差＝接続**、**CP/中継/矢印＝別シート・場外へ**。
  これらは図面上に“線”として存在しないため、機械のトレースは取りこぼす／繋ぎ過ぎる。
- 実測（7製番）：結線を「形成できた率」は 70〜98% だが、ハーネス（正解）と突き合わせた
  **整合率は 20〜65%** にとどまり、**誤接続（例: 号線1GCR が近くの別機器 27X に誤結合）** が発生。
  さらに制御配線の多くは盤ハーネスに号線名が無く、**自動抽出の正しさを機械的に検証しきれない**。

結論：**正確な From-To は「設計が持つ結線の意図」を構造データで受け取るのが唯一確実**。
これは既存の -DCT（ロケータを DEVICE1='レール-文字' で図面に書き出す仕組み）と同じ発想。

---

## 1. データモデル（2層）

結線は電気と物理の2層に分けて考える。

### ① 等電位ノード（電気・一意に決まる）
- 定義：同電位で繋がる端子の集合。**号線＝ノード名**。母線は「横に長い1つの端子」＝1ノード。
- これが結線の“電気的な真”。**一意に決まる**ので、ここを 100% 正しく持つのが目標。

### ② 物理配線（渡り・一意ではない）
- 定義：ノード内を実際にどう1本ずつ配線するか（端子↔端子のペア列）。
- 端子A・B・Cが等電位なら A-B,B-C でも A-B,A-C でもよい＝**木の選び方＝非一意**。
- よって「人と同一の渡り」を狙わない。**規則（端子結線数上限・最近傍・端子台の並び）で生成**、
  または設計が指定するなら受け取る。

> 検図・正解率は**①ノード単位**で判定する（②渡りの順番違いは電気的に同じなので誤りに数えない）。

---

## 2. 接続点の種類（アドオンが直接知っている情報）

線端が繋がる先は、次のいずれか。アドオンは設計時の実体を知っているので**推測不要**で出力できる。

| 接続点 | 説明 | 図面での見え方（参考） |
|---|---|---|
| 機器の端子 | 機器記号の端子ピン | 端子番号(TERMINAL) |
| 端子台の端子 | 端子台ラグ | _LU ブロック等、番号=DEVICE1 |
| 線 | 別の線への接続（T字・継続） | 端点が線に載る |
| 接続点ドット | 交差での接続 | `_crossPoint1` ブロック |
| コネクタ(CP) | 別シート/ケーブルへ | DEVICE=CP、DEVICE1=番号 |
| 中継端子台 | 中継 | TB-中継 等 |
| 信号ボックス | 計装信号等の枠 | 四角形＋±/SE |

## 3. 出力スキーマ

### 3.1 号線（等電位ノード）— 必須・第一級データ
```json
{
  "seiban": "5-12110",
  "nodes": [
    {
      "gousen": "1ACR",            // 号線＝ノード名
      "kind": "main",              // main(主回路) / ctrl(制御) / earth(アース)
      "wire_type": "HIV",          // 電線種別
      "size": "2",                 // 電線サイズ
      "color": "赤",               // 色（任意）
      "members": [                 // このノードに繋がる 機器:端子（すべて）
        {"device": "MCCB-1A",  "terminal": "2"},
        {"device": "MCCB-1AC", "terminal": "1"},
        {"device": "TB-C",     "terminal": "1ACR"}
      ]
    }
  ]
}
```

### 3.2 物理配線（渡り）— 任意（無ければ製造側が規則生成）
```json
{
  "gousen": "1ACR",
  "wires": [                       // ノード内の端子ペア列（渡り含む）
    {"from": {"device":"MCCB-1A","terminal":"2"},  "to": {"device":"TB-C","terminal":"1ACR"}},
    {"from": {"device":"TB-C","terminal":"1ACR"}, "to": {"device":"MCCB-1AC","terminal":"1"}}
  ]
}
```

### 3.3 ロケータ（据付位置）— 既存 -DCT と同一
- 端子台/機器ブロックの `DEVICE1 = "{レール}-{文字}"`（例 `2-B`）。
- 既存の -DCT 出力をそのまま踏襲。

---

## 4. 図面への書き出し方（アドオン実装）

設計CADのアドオンは、上記を**図面エンティティの構造データ**として書き出す。方式は2択：

- **A-1: 電線に XData**：各電線ポリラインに `GOUSEN / FROM(機器:端子) / TO(機器:端子) /
  WTYPE / SIZE / COLOR / DUCT` を付与。
- **A-2: 端子に属性**：各機器端子に `CONNECT_GOUSEN=号線` を付与。号線でまとまる端子集合＝ノード。

いずれでも、製造側は幾何推測なしにノード（§3.1）を復元できる。既存の -DCT が DEVICE1 に
ロケータを書くのと同じ仕組みで、**設計が持つ結線意図をそのまま渡す**のが要点。

---

## 5. 製造側（本Pythonシステム）の役割分担

アドオン(A)が From-To（①ノード）を出す → 本システムが以下を生成する。

1. **② 物理配線（渡り）を規則生成**（端子結線数上限・最近傍デイジーチェーン・端子台の並び）。
2. **物理付帯情報**：LUG/WAGO/中継/渡り/ダクト方向/扉/セル/ロケータ。
3. **成果物**：ハーネスシート／主回路／検図／1本ずつ表示。
4. **検図**：号線ラベルはあるがノードに機器が2つ未満、端子台番号(DEVICE1)未記入、等を設計へ差し戻し。

---

## 6. 段階計画

- **フェーズB（現行・試作）**：Python＋Web UI「結線確定ナビ」。図面から自動抽出した
  From-To を**下書き**として図面上に提示し、**現場が確認・修正して確定**（自動は当たり付け、
  確定は人）。ここで確定した From-To が §3 のスキーマと一致するよう運用し、**仕様を固める**。
- **フェーズA（本命）**：仕様確定後、設計CADアドオンが §3/§4 で From-To を書き出す。
  以後は**推測ゼロ・検証不要**で、製造側はそのまま消費する。

---

## 7. 検図で設計へ返す項目（図面のみで検出可能）

- 号線ラベルはあるがノードに機器が2つ未満（未結線）
- 端子台ラグの番号(DEVICE1)未記入（`*`/空）
- 号線の無い電線／機器記号(DEVICE)欠落
- 母線メンバーが線で辿れない（帯としての明示が必要）
