# ハーネスデータ自動生成システム 運用マニュアル

図面（DXF）から人手同等のハーネスデータを自動生成し、モデルと同一フォーマットの
Excel を出力して既存のシール印刷システムに取り込むための社内Webアプリです。

## 1. 起動（社内サーバ）
```
# 依存の導入（初回）
pip install -r wireharness/requirements.txt

# 開発起動（動作確認用）
python wireharness/harness_app.py          # http://<サーバ>:8000

# 本番起動（推奨・常駐）
gunicorn -b 0.0.0.0:8000 wireharness.harness_app:app
```
- **AWS(EC2)への配備**は見積システムと同形態（systemd+gunicorn+nginx・別ポート8002・社内限定）。
  手順は `deploy/AWS_ハーネス_デプロイ手順.md`、定義は `deploy/harness-system.service` /
  `deploy/nginx-harness.conf` / `deploy/harness-system.env.example` を参照。
- 永続化: `HARNESS_WORK`(アップロード/出力/ログ/バックアップ) と
  `HARNESS_STATE`(学習結果 learned.json/design_cases.json/confirmed) を `/var/lib/harness-system/`
  等の永続領域に向ける（未設定ならパッケージ内＝ローカル挙動のまま）。再デプロイで学習は巻き戻らない。
- 作業データの保存先は環境変数 `HARNESS_WORK`（既定 `wireharness/harness_work/`）。
  社内サーバでは永続ディスク上のパスを指定してください（例 `HARNESS_WORK=/srv/harness_work`）。
- 常駐化（任意）: systemd のサービス化や `nohup gunicorn ... &` 等、社内手順に合わせて設定。

## 2. 画面と操作
- **ホーム `/`**：製番一覧・図面アップロード・設計不備の登録導線。
- **一括生成**：製番＋図面DXF一式 → `produce_seiban` → 確認UIへ。
- **確認UI `/review/<製番>`**（3工程）
  1. ①設計不備：指摘に「設計へ戻す／製造で手直し」を選ぶ。
  2. ②ハーネス確認：黄色＝要確認を修正/確認。
  3. ③確定・出力＋学習：モデル同一形式の Excel/txt を出力（既存システム取込→シール印刷）。
     人手修正は学習に反映（差分のみ・回帰ゼロ）。
- **出力一覧 `/outputs/<製番>`**：Excel/txt/CSV のダウンロード。
- **単独検図 `/check`**：ハーネス生成とは別に図面だけを検査。検図システムと同一エンジン
  （R1-R7＋H1-H5＋AI補助＋学習済み見逃しルール）を本アプリに統合。結果は{場所/問題/提案/根拠}様式。
  現場の見逃しは『見逃し登録』で学習（defect_rules、HARNESS_STATEに永続）。
- **設計不備の学習 `/design`**：修正前/後の図面(DXF)を登録 → before→after差分で学習。過去ケース一覧。
- **管理 `/admin`**：学習結果のバックアップ状況・手動バックアップ・ログ末尾。
- **使い方 `/help`**／**ヘルスチェック `/api/health`**。

## 3. 二つの学習ループ
- **A 設計不備の学習**：製番ごとの3点セット（修正前図面／不備内容／修正後図面）。
  不備内容は①改訂履歴②【修正箇所】PDF③before→after差分で裏取り。
  2層（誤答ゼロ）: 層1=横断検証で過検出ゼロのルールのみ自動検出（R2容量逆転=スケルトン限定／R3中性線端子V→N）、
  層2=断定しない参考（R7接地 等）。修正案は実績由来でAIは創作しない。`design_cases.json`。
- **B 出力確認の学習**：③確定時に人手の修正差分だけを権威学習。既存知識は保持。`learned.json`／`confirmed/`。

## 4. バックアップとログ
- **学習結果**：`learned.json`／`design_cases.json`／`confirmed/`。学習のたびに自動で
  `HARNESS_WORK/_backup/<日時>/` に退避（直近30世代）。`/admin` で手動退避も可能。
- **リポジトリ側**：`learned.json`／`design_cases.json` は Git にコミットして版管理。
  図面（DXF/PDF）は容量が大きいため Git には含めず Dropbox（原本）で管理。
- **ログ**：`HARNESS_WORK/logs/app.log`（ローテーション 1MB×5）。生成/確定/学習/エラーを記録。

## 5. 出力フォーマット（重要）
- ハーネスデータは**モデルと同一フォーマット**（11列：タイトル/製番/仕様ヘッダ/端点2行/区切り）。
- `<製番>_ハーネスデータ.xlsx` を既存システムに読み込ませてシールシートへ印刷。
- ラベルの直接印刷は**第二弾の印刷機能**として保留（生成コードは温存）。

## 6. トラブル時
- 画面にエラーが出たら `/admin` のログ末尾、または `HARNESS_WORK/logs/app.log` を確認。
- 学習結果を戻したい場合は `_backup/<日時>/` の該当ファイルを
  `wireharness/fromto_qc/` に上書きで復元。
- 図面が読めない（文字コード等）場合は cp932 の DXF を想定。生成が0件・異常な場合はログを添えて連絡。
